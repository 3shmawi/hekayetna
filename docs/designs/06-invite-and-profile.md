# Spec 06 · Invite family (WhatsApp, QR, short code) and display names

Status: ready for review · PR title: `feat: invite family by WhatsApp or QR, and choose your display name`
Branch: `feat/06-invite-and-profile` · Depends on: 01, 03 · Flag: none

## Why

Families join an app when someone sends a WhatsApp message or shows a QR
code at the table, not by typing a UUID. Members also appear by the first
part of their email address today; they should appear by the name the
family uses.

## Scope

### 1. Backend: migration `0010_invite_codes.sql`

- `family_spaces.invite_short_code text unique not null`, 7 characters from
  the alphabet `23456789ABCDEFGHJKMNPQRSTUVWXYZ` (no 0/O/1/I/L), generated by
  a `before insert` trigger; backfill existing rows.
- `join_family_space_by_code(p_code text) returns uuid` (security definer):
  normalises (uppercase, strips spaces and `-`), same rules as
  `join_family_space` (removed members blocked). Errors: `member_removed`
  for a removed member (the UI explains it), `invalid_invite_code` for
  anything else.
- `rotate_invite_code(p_space uuid) returns text` (owner only): new short code
  and new UUID invite code; old ones stop working at once.
- pgTAP: anon can't call either; a member can't rotate; the owner can; old
  code fails after rotation; removed member is blocked; codes are unique.
- Keep the UUID `join_family_space` for old links.

### 2. Invite screen (`InvitePage`), per artboard IdeaInvite

- Opened from: family tree header (invite icon), person sheet "Add a
  relative → Invite them", and the empty family state.
- Text: "At the dinner table? Let them scan this with their camera. They'll
  join the {family} family after signing in." (both languages).
- QR code of the link `familystories://join/<SHORTCODE>` (and, once the
  website domain is verified, `https://<domain>/join/<SHORTCODE>`; read the
  host from config, not hard-coded). Package: `qr_flutter` (pin exact
  version). Quiet zone and dark modules in `onSurface` on a white tile, even
  in dark mode (scanners need contrast).
- **Send on WhatsApp** (WhatsApp green background, white label: the one
  allowed brand colour, add it as `AppColors.whatsapp` with a comment):
  opens `https://wa.me/?text=<message>` with url_launcher; message: "Join
  our family on Hekayetna to hear our stories: <link> (code 7K4-QM9)" in the
  app's language. If WhatsApp isn't installed the link opens in the browser,
  which is fine.
- **Share another way**: system share sheet (`share_plus`, pin exact version).
- Short code shown as `7K4-QM9` with **Copy** (copies without the dash,
  message "Code copied").
- Owner only: **Change the code** in a More menu, with a confirmation
  ("Old links and codes will stop working").
- Footer line: "New members only hear stories shared after they join."

### 3. Joining

- New route `/join/:code` (name `join_family`), signed-in only (signed-out
  users go to sign-in and come back, existing `from` logic). It shows a
  confirm screen: family name (fetched by an RPC
  `preview_family_by_code(p_code) returns table(name text, member_count int)`
  callable by authenticated users only, no other data), **Join {family}**
  and Cancel. Errors: invalid code, removed member (explains they were
  removed and must ask the owner), already a member (just opens the family).
- The create-or-join screen accepts the short code (case-insensitive, with
  or without the dash) and old UUID codes.
- Add the route to `AppRoutes`, `app_router.dart`, `docs/deep_links.md`;
  Android intent filter / iOS URL type already cover the scheme (verify).
  Security tests: hostile codes (`../`, 10 000 chars, `%00`, emoji,
  `javascript:`) never crash and never call the RPC with junk (validate
  `^[0-9A-Z-]{6,9}$` or a UUID first).

### 4. Display name

- After the first create or join (and in Settings → Account → **Your name**),
  ask "What does the family call you?" with one field (1–40 chars, trimmed),
  prefilled with the current `display_name`. Saved to `profiles.display_name`.
- Everywhere a member is shown, use `display_name`, never the email.

## Acceptance criteria

- **AC-1** Migration 0010 + pgTAP tests pass (all cases above).
- **AC-2** Invite screen matches the artboard (goldens light/dark × en/ar);

- **AC-3** WhatsApp, share and copy call the right platform APIs with the

- **AC-4** Rotate code is owner-only in UI and backend; old code fails.
- **AC-5** `/join/:code` flow: signed-out → sign-in → back to confirm; join
  succeeds; removed/invalid/already-member states (widget tests).
- **AC-6** Deep-link security tests added; all pass.
- **AC-7** Display name prompt after first create/join and in settings;
  emails never shown for members (grep test over `lib/features` for
  `.email` use in widgets, or a widget test with a member without a name).
- **AC-8** Integration test (demo style): open invite, copy code, open the
  join link in a second demo user session, confirm, see the family.
- **AC-9** Docs: `docs/features/invite.md`, `docs/deep_links.md`,
  `docs/backend.md`; privacy policy unchanged (no new data) — say so in the PR.
